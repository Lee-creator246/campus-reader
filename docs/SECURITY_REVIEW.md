# 第 7 版安全审查说明

日期：2026-11-03。对象：`0.7.0-campus`。本轮采用 [Cloudflare security-audit-skill](https://github.com/cloudflare/security-audit-skill) 的范围划分、独立研究、候选反证和覆盖记录方法，选择 quick 范围源码审查。参考版本为 `c1c8a8c1471069fb0e188eeaff69b8e8db6564a8`。

## 范围和本版改动

检查重点为门户密码保存与自动恢复、学校目录输入、账号与站点隔离、WebView 和 HTTP 认证边界、媒体分享以及 AI 请求和密钥的分离。专有 SDK 二进制、完整供应链、其他阅读器数据路径和所有 Android 系统运行行为未纳入完整审查。

本版对审查过程中涉及的路径做了以下加固：

- 门户固定密码用 AndroidKeyStore AES-GCM 加密，绑定站点、账号与已确认的精确 HTTPS 认证目标；动态码不保存，未知表单不自动填密。
- 门户、同步和媒体请求把会话代次及取消检查传到实际 Cookie 写入；重新获取正文共用刷新锁，并在写库前检查请求有效性。
- 每次媒体文件提交产生独立版本，分享 URI 绑定该版本。数据替换前先撤销旧元数据；版本验证与文件打开同锁执行。
- 学校目录严格限制字段、体积、数量和地址，目录导入与 SDK 服务同意分离。

两个正式媒体候选经另一位审查者对修改后的源码进行反证后判为 rejected；这表示原候选描述的普通路径已不成立，不等于所有攻击或生命周期情形均已验证。审查末尾指出的正文补取覆盖缺口及媒体提交中断路径已由开发侧加固，但本轮未完成新一轮独立动态验证。

## 未完成的审计门槛

严格审计状态为 **incomplete**，不能作为“安全认证”或“没有漏洞”的证明。

- 当前 Windows 环境不能提供该 skill 要求的无网络、只读目标、独立写入目录和资源限制的操作系统强制沙盒。遵守其执行约束，仅做源码审查，没有在安全审查角色内运行目标代码。
- 上游 CLI 校验器要求的 no-follow / nonblocking 输入保护在当前 Windows 平台不可用，因此其 CLI 门槛未通过；没有修改上游脚本来绕过保护。通过导出的验证 API 检查可信内存对象，也不能替代完整 CLI 门槛。
- 没有真实设备或校园账号参与本轮审查；WebView Cookie 排序、KeyStore、系统 URI 授权和进程中断行为仍需受控设备验证。

普通开发回归、签名和已知敏感标记扫描独立记录在 [VALIDATION.md](VALIDATION.md)。回归测试使用合成数据和主机替代实现，不计为上述审计漏洞复现证据。公开仓库保留本说明；详细工作记录保存在维护者本机，避免上传开发路径或环境资料。
